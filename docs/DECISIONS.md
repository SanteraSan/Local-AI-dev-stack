# Журнал решений

Почему сделано так, а не иначе. Формат: контекст, решение, последствия. Новые записи добавляются сверху. Замеры и ход экспериментов — в `JOURNAL.md`.

## 2026-10-17. Отдельный лабораторный журнал

Контекст: замеры и сбои записывались прямо в решения, и решения разрастались.

Решение: `DECISIONS.md` отвечает на «почему так», `JOURNAL.md` — на «что пробовали, что намерили, что сломалось», в формате журнала TaskFlow. `README.md` — текущее состояние.

Последствия: после каждой фазы обновляются все три документа.

## 2026-10-17. qwen2.5-coder не используется для нативного вызова инструментов

Контекст: с инструментами в запросе `qwen2.5-coder` пишет JSON вызова текстом, `qwen3:14b` делает настоящие `tool_calls` (замеры — в журнале).

Решение:

- в Open WebUI для `coder` выключен нативный вызов функций; для чата с инструментами — `reasoner`; служебные задачи Open WebUI — `fast`;
- модель для роли `coder` в агентах с tool calling выбирается проверкой перед фазой 4 (кандидаты `qwen3:14b`, `qwen3-coder:30b`);
- `qwen2.5-coder` остаётся для чата о коде, правок без инструментов (Aider) и автодополнения.

Последствия: при смене модели меняется одна строка в `litellm/config.yaml`, клиенты не трогаются.

## 2026-10-17. Шлюз LiteLLM: сеть, ключи, логи, версии

Контекст: Ollama слушает только `127.0.0.1` хоста и без авторизации; шлюз должен быть единственной точкой входа.

Решения:

- LiteLLM и Open WebUI в `network_mode: host`, явно на `127.0.0.1`. В bridge-сети контейнер не видит `127.0.0.1` хоста, а открывать Ollama на `0.0.0.0` нельзя. Open WebUI по умолчанию слушает `0.0.0.0`, поэтому `HOST=127.0.0.1`;
- `keep_alive: -1` для `coder` и `fast` в конфиге шлюза, иначе каждый запрос сбрасывал бы прогрев на глобальные 30 минут;
- отдельный виртуальный ключ на клиента, ключ devmem ограничен `embed`;
- `turn_off_message_logging`: в журнал расходов идут метаданные, не тексты;
- Open WebUI считает эмбеддинги через шлюз, а не качает модель с Hugging Face;
- образы закреплены по digest после первой рабочей сборки.

Последствия: облачный fallback подготовлен, но выключен до появления ключа.

## 2026-10-17. TOON — эксперимент, а не формат по умолчанию

Контекст: TOON экономит токены на однородных списках объектов, окно локальной модели 32k.

Решение: сериализация ответов devmem сменная (`json | toon | csv`), по умолчанию компактный JSON. Формат по умолчанию выбирается по бенчмарку: входные токены и точность на `coder`, `reasoner`, `reviewer`.

Последствия: протоколы (MCP, tool calling) и ответы модели остаются JSON; TOON только в тексте ответа инструмента.

## 2026-10-17. Память агентов — MCP-сервер на Postgres + pgvector

Контекст: нужна общая память между сессиями, клиентами (Cursor, Roo, Continue, OpenCode) и моделями.

Решение: отдельный MCP-сервер `devmem` с явными инструментами (решения, итоги шагов, handoff), а не перехват трафика в шлюзе и не файлы в репозиториях. Существующие документы проектов импортируются как записи с `source_path`. Дообучение моделей на файлах репозитория не используется.

Последствия: память — контекст, а не доказательство; агент сверяет записи с кодом. Перезагрузку модели память не решает: история не теряется, клиент присылает её заново.

## 2026-10-17. Порядок загрузки моделей фиксирует warmup.sh

Контекст: `coder` и `fast` помещаются в 16 ГБ, только если `coder` загружается первой; Ollama выбирает размещение один раз при загрузке.

Решение: `ollama/warmup.sh` выгружает все модели и загружает пару в порядке `coder`, затем `fast`, с `keep_alive: -1`.

Последствия: после фаз `reasoner` / `reviewer` прогрев нужно повторять. В будущем — автопрогрев хуком в LiteLLM.

## 2026-10-17. Раскладка моделей под 16 ГБ видеопамяти

Контекст: глобальное окно 16384 раздувало маленькие модели, рабочий стол GNOME использует видеопамять NVIDIA.

Решение: варианты через Modelfile — `coder` с окном 32768, `fast` с окном 4096, эмбеддинги целиком на CPU (`num_gpu 0`). KV-кэш `q8_0` и flash attention включены глобально. Аппаратное ускорение Chrome выключено.

Последствия: при нехватке памяти сначала освобождать видеопамять (монитор на встроенную графику), и только потом уменьшать окно `coder`.

## 2026-10-17. Отдельный репозиторий для личной AI-инфраструктуры

Контекст: шлюз и память нужны во всех проектах, а не только в TaskFlow.

Решение: `~/dev-ai-stack` — отдельный репозиторий. Клиенты обращаются к псевдонимам по ролям (`coder`, `fast`, `reasoner`, `reviewer`, `vision`, `embed`), а не к реальным именам моделей. Всё слушает только `127.0.0.1`.

Последствия: правки в TaskFlow не ломают инструменты разработки. TaskFlow позже подключается к шлюзу как ещё один провайдер своего `ModelGateway`.
